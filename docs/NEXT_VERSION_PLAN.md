# 本轮优先需求清单（2026-09-16，v0.12.0）

用户明确要求优先处理以下两部分，均列为P0。本轮业务规则已确认并实现，最终发布证据见[验证记录](VERIFICATION.md)，配置方式见[版本说明](V0.12.md)。以下待细化事项保留为讨论历史，其最终决策以[已批准设计](superpowers/specs/2026-09-16-redundancy-support-workflows-design.md)为准。

| 编号 | 优先级 | 开发需求 | 范围与验收目标 |
|---|---|---|---|
| EQ-KN | P0 | 装备n中取k逻辑 | 配置一个部件组的n与最低可用数量k，按可用数量判定组状态；故障、维修、换件、报废后的状态变更须正确传递到装备可用性和任务判定。其他装备能力不纳入。 |
| SUPPORT-FLOW | P0 | 保障活动多工序及紧前/紧后关系 | 一项保障活动可定义多道工序，各自配置耗时、人员/设备；支持依赖约束下的串行、并行与汇合。全部紧前工序完成且资源满足后才能启动后续工序；界面可查看紧前/紧后关系。 |

## 进入实现前需要细化的业务规则

- EQ-KN：可配置组的层级及分组边界；组内健康部件是否全部运行；低于k时的任务处理；尚满足k时故障件何时维修。不能把热备、冷备或飞行中止规则当作已确认。
- SUPPORT-FLOW：首批接入的活动类别（再次出动准备、修复性/预防性维修等）；同一装备允许的并行约束；工序资源释放、跨班及异常中断处理；现有单作业与固定维修工序的兼容方式。

## 验收重点

- n中取k边界：恰好k件可用、从k降到k−1、修复后恢复到k、同刻状态变化；未配置新规则时保持旧串联模型行为。
- 工序网络：单链、分叉并行、多个紧前汇合；资源不足时排队；循环依赖和无效引用拦截；活动完成时点由实际工序完成决定，不能简单相加所有并行工序时长。
- 两项均须覆盖中文建模、运行轨迹、结果与导出、历史项目兼容及桌面验收。

## 暂缓范围

其他装备能力、任务相关能力降级、任意深结构和混合编队暂不增加；供应中断、横向支援及运输容量等排在上述两项之后。此清单不代表这些后续功能已经获得实施授权。

## 运行小时检查：已确认规则（2026-09-15）

用户选择A：起飞前剩余检查小时不足以覆盖本次任务时仍允许起飞；空中达到检查阈值不因本项检查中止飞行，落地后执行检查，到期后不得领取新任务。例如剩余2小时、任务3小时：飞行第2小时到期，落地后检查，记录超出1小时。随机故障仍按既有中止返航规则处理。

用户随后确认：检查实际完成后，本项检查累计小时归零，从完成后重新累计一个完整检查间隔；超出阈值的飞行小时保留在历史记录中，不扣减下一周期。部件年龄及故障时钟不重置。例如间隔100小时，实际101小时落地检查，完成后再累计100小时到期。

用户进一步确认以下三项：

- 飞行小时从起飞累计到落地，包含中止返航；地面等待、准备及维修不累计。
- 支持逐架设置距上次检查已飞小时，默认0；该计数不是部件年龄。
- 与日历维修同时到期时，两项分别串行执行，不相互抵消；全部完成后统一进行一次再次出动准备。实际作业时长相加，资源等待另算。

上述规则已实现，计时、共享维修队列、中文输入、首轮结果及全轮CSV已接入；验证记录见VERIFICATION.md。

### 下一增量验收重点

1. 剩余2小时、任务3小时：飞行第2小时记到期，落地后检查，记录1小时超限；不会仅因检查到期中止飞行。
2. 出航、任务区、正常/中止返航均累计，地面状态不累计；不同飞机的初始小时和后续计时独立。
3. 检查完成后本项计时归零，部件年龄和故障时钟保持；超限不从下一完整周期扣除。
4. 日历维修1小时与运行小时检查2小时同时到期：串行作业共3小时，完成后只做一次准备；资源不足另计等待。
5. 验证阈值恰逢落地、期末未完成、故障维修冲突、历史项目兼容和不启用新规则时的旧案例回归。
