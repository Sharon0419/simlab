# M2 部件老化与维修年龄设计

日期：2026-09-15。用户已明确“设计评审通过”。当前交付 v0.9.2；本设计已实现并验证，详见 docs/VERIFICATION.md。

## 已确认约束

- 故障维修默认修复如新。
- 飞行小时检查完成只清零该项检查计时，不改变部件年龄或故障时钟。
- 今天目标完成 M2，交付包含老化、维修年龄更新、中文输入与结果、验证和桌面程序。

## 实现方案

沿用 Components 实物身份和叶子故障预算，增加运行年龄及累计风险计算。无老化配置的模型继续走原有路径，保留旧种子下的历史轨迹。启用老化的模型统一按实物叶子计算，覆盖直接 LRU 与 LRU/SRU 两种结构。

不采用仅修改整机故障率的方案，因为它不能保存拆下返库后部件的真实年龄；不引入日历腐蚀等另一套时钟。

## 输入契约

新增独立扩展表 SimLabItemAging，每类叶子一行：

| 字段 | 含义与约束 |
| --- | --- |
| IID | 叶子部件，带子件的 LRU 不允许配置 |
| SHAPE | Weibull 形状参数，默认 1，允许 1 至 10 |
| SCALE_H | Weibull 尺度，至少 0.000001 运行小时；不是平均寿命 |
| INITIAL_H | 初始装机件有效运行年龄，默认 0 |
| REPAIR | PERFECT 默认修复如新；MINIMAL 最小修复 |

同类初始装机件共用初始年龄；初始库存按新件年龄 0。这一版不支持逐个序列号导入不同年龄。未配置的叶子继续使用 Item.FRT 指数模型。配置 Weibull 的叶子要求 FRT=0，避免叠加或静默忽略两套输入；AFFRT、各层 ENVF 继续作为风险倍数。

## 时钟与寿命

有效年龄按实际运行时长乘 UTIL 累计。任务模式只在实际执行任务时运行；飞行包括中止返航。待命、准备、维修、库存和运输暂停。故障子件停止累计；故障返航中仍工作的健康子件继续累计。累计终身运行小时另行保留，修复不清零。

基础累计风险 H(a)=(a/SCALE_H)^SHAPE。每次新寿命周期抽取单位指数风险预算 E；从已有年龄 a 开始，未来运行增量 x 满足 multiplier×[H(a+x)-H(a)]=E。使用条件剩余寿命，不能重新从年龄 0 抽样后减去初始年龄。风险倍数不改变记录的运行年龄。

SHAPE=1 时退化为指数寿命；此等价是统计及解析关系，不要求新旧随机调用顺序逐样本相同。仿真时长到达时必须结算最后一段尚未触发事件的年龄。

## 维修与实物流转

PERFECT 在实际修复完成时将被修叶子有效年龄置 0，并开始新风险预算。MINIMAL 保留有效年龄，从该年龄开始抽取新的条件风险预算。两者都保留终身运行小时和维修历史。

维修父 LRU 的流程仍通过更换故障 SRU、检测与测试恢复总成；不能因此清零其余健康 SRU。拆装、返库、运输和再次装机保存实物身份与年龄。检查和日历计划维修不使部件年轻化。

## 验收清单

1. 固定风险预算下，SHAPE=1 与解析指数时刻相同；SHAPE=2 的已有年龄条件寿命与解析值一致。
2. 任务间待命、准备、库存和运输不增龄；UTIL 缩放年龄，ENVF 仅缩放风险。
3. PERFECT 修复后有效年龄为 0；MINIMAL 保留年龄；終身运行小时均不减少。
4. 同总成健康兄弟件、返库件及换装件身份和年龄保持，直接 LRU 也适用。
5. 检查计时清零不影响部件年龄；随机故障仍按既有返航规则，空中不维修。
6. 期末在飞、等待维修、修复尚未完成等状态年龄结算正确，无重复计时。
7. 参数不合法及故障规模不合理时在运行前报中文错误；禁止非有限值。
8. 旧案例无新配置时保留数值及事件回归；完整 pytest、源码及打包桌面检查通过。
9. 新老化案例对比 PERFECT/MINIMAL，核对年龄与时间守恒；源码、保存结果和 EXE 同种子一致。
10. 更新中文说明、案例包、验证记录、Obsidian 进度，安装桌面程序并核验 ZIP 完整性。

## 独立解析验收依据

来源：[NIST Weibull 可靠性公式](https://itl.nist.gov/div898/handbook/apr/section1/apr162.htm)，2026-09-15 查阅。NIST 给出 R(t)=exp[-(t/α)^γ]、H(t)=(t/α)^γ，均值 αΓ(1+1/γ)。以下条件剩余寿命与样例由这些公式推导，属于本项目验收依据，不是原厂 SIMLOX 对照。

给定当前年龄 a、尺度 η、形状 β、正风险倍数 m 和单位指数预算 E，新增运行年龄为 x=η[(a/η)^β+E/m]^(1/β)-a。日历等待时长为 x/UTIL；UTIL=0 时不消耗预算。

固定数值预言机（测试直接断言这些值，不调用生产公式生成期望值）：

| 场景 | 参数 | 预期新增运行年龄 |
| --- | --- | --- |
| 指数与已有年龄 | β=1，η=100，a=60，E=0.4，m=1 | 40 小时 |
| 已使用部件 | β=2，η=100，a=60，E=0.64，m=1 | 40 小时 |
| 新部件同预算 | β=2，η=100，a=0，E=0.64，m=1 | 80 小时 |
| 风险倍数 | β=2，η=100，a=60，E=1.28，m=2 | 40 小时 |
| 最小修复后 | β=2，η=100，a=100，E=1.25，m=1 | 50 小时 |
| 修复如新后 | β=2，η=100，a=0，E=1.25，m=1 | 约 111.803398875 小时 |

第二行若 UTIL=0.5，连续运行模式经过 80 个日历小时才故障。若任务只运行 20 日历小时后待命 100 小时，再运行 60 日历小时，则在时刻 180 故障；待命不贡献年龄。ENVF=0 时风险为零，但运行年龄仍应累计。

数值稳定性验收：大年龄与小预算组合不能因两大数相减得到零寿命而造成无限同刻循环；实现应采用稳定的增量计算，并对不可表示的输入范围报错。参数边界必须由稳定性和事件规模证据支持，不能只保证输入为正。
