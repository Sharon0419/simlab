# v0.9 日历计划维修使用说明

该版本补齐M2中的固定飞行日历计划维修子集；运行小时触发、老化、多工序及原厂对照仍未实现。

## 打开示例

从项目库打开“飞机日历计划维修 · 12架 · 1000次”，或导入docs/cases/2026-09-15-aircraft-planned/飞机日历计划维修.simproj。
案例新增每天10点到期、每架维修1小时、共享2个保障组；为合成验证条件，不是实际维修制度。

## 设置自己的规则

进入“模型数据 → 04 维修与保障作业 → 日历计划维修”，添加一行：

1. 计划维修标识：自行命名且不重复。
2. 系统标识、单位/站点：与系统部署中的位置一致；该部署每架飞机都会触发。
3. 首次到期时刻：从仿真开始计的绝对小时。
4. 重复间隔：例如24表示每天；0或留空只触发一次。
5. 固定维修时长：以小时计，必须大于0。
6. 维修资源作业：选择已配置资源需求的作业；留空表示无限资源条件下执行。

系统到期后不再起飞；在飞先落地，已有故障维修或准备先完成。计划作业按资源和班次排队，不抢占；结束后仍需完成再次出动准备。每天首波默认准备好的假设不能跳过这些步骤。

## 查看结果

“结果分析 → 日历计划维修”显示到期、申请资源、开始、结束及延后/等待/实际作业时长，支持导出全部轮次CSV。
“停机原因”新增计划维修等待资源和计划维修作业；“取消原因”显示计划维修到期或执行中。
可用度包含计划维修排队和作业停机；延期等待落地及前序工作的时间单列，不能重复扣除。

新版本能打开旧项目；保存后的格式7项目不能由v0.8打开。旧历史结果保留，新指标需要重新运行才能产生。
完整规则见[V0.9-SPEC.md](V0.9-SPEC.md)，验证见[VERIFICATION.md](VERIFICATION.md)。
