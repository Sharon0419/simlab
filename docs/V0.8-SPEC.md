# v0.8 实施契约：项目库与再次出动保障

2026-09-11，用户已授权实施。半小时为回收后到重新具备出动条件的全部准备时间，本版作为一个完整作业；后续再拆分多个工序，不在本版重复计回收与出动前两次半小时。

## 范围

1. 统一项目库：扫描应用项目目录及曾打开的外部项目，显示名称、说明、最近运行、引擎版本和路径；支持打开、复制模型为新方案、导入项目包。原cmd兼容保留，不删除数据库。
2. 在SimLabFlightRule增加可选PREP_TASK，引用现有Tasks/TaskResource；ResourceAllocation控制容量，ResourceStationData/ShiftProfile控制班次。沿用站点FIFO、组合原子申请、班内启动跨班继续；资源可与维修共享。不填写新选项则保留v0.7行为。
3. 半小时从资源全部到齐后开始，等待不算作业，完成释放资源且飞机就绪。仅健康且已落地飞机进入准备，故障飞机完成修复后进入。保障过程中无随机故障暴露。
4. 用户确认DAILY_READY=Y：每天首波健康地面飞机假定已提前保障好，不能自动修复故障或提前释放在飞飞机。健康飞机未完准备记录assumed_ready并释放资源，保留已发生等待/工作时间，不计正常完成；测试跨日、在做/等待接续和不修复故障。此假设排除首波实际保障资源需求。
5. 同刻准备完成先于起飞判定，准备未完不能参加；准点不足取消，不引入延迟起飞。
6. 输出每次准备的排队/开始/结束、资源及状态；汇总等待资源/班次、作业小时、完成与未完作业。取消保留就绪快照和可解释分类，避免将全部取消都归于故障。

## 文件职责

project_library.py负责本地目录元数据与模型复制，ui/library.py负责项目库界面；ground.py负责单个准备作业与资源占用，不改变故障模块；flight.py协调就绪和起飞；operations.py/compiler.py处理字段与容量；engine.py聚合；ui/window.py和flight_results.py负责显示与导出。原SIMLOX字典不变，独立扩展格式升级6。

## 限制

不实现工序网络、计划维修、抢占、DTIM延迟起飞、阶段故障倍率或优化算法。2组是可修改的案例假设，不是实际机场配置建议。原厂数值等价仍未认证。
