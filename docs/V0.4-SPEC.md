# v0.4 固定时段值守实施计划

目标：固定起止窗口内持续保障，记录供给缺口和最低保障不达标；不推迟终点，不自动中止窗口。

架构：沿用 MissionManager 分配与事件积分。增加独立 SimLabDutyRule 表按任务类型配置最低数量、优先级、补位小时和允许连续不达标小时；原表字段语义不变。桌面新增值守计划页，复用原项目保存和后台计算。

技术：Python / SimPy / PySide6 / SQLite。

## 冻结规则

- 无扩展规则：最低数量=目标数量，优先级=1，补位时间=0，容忍时间=0；旧供给与故障结果保持。
- 最低数量为1至目标数量整数；优先级为正整数且越小越优先；补位与容忍小时非负有限。
- 开始时可用设备直接值守；窗口开始之后的任何新分配均需补位准备时间。准备期间设备独占但不供给、不累计运行故障；故障或窗口结束取消准备，过期回调不得影响后续任务。
- 已值守和已预留设备不被高优先级任务抢占；同时等待时按优先级、开始时间、标识分配。
- 目标缺口照常累计。低于最低数量的时间按窗口计时；最长连续不达标时长不大于容忍时间即窗口合格（边界容差1e-9小时）。补齐不消除过去记录。
- 总达标率按各任务窗口小时加权；窗口合格率按窗口数；不是原厂任务成功率。
- 首轮不达标区间上限5000条，截断标识明确；总指标不截断。
- 日历批量编辑按从仿真起点起的第1天生成绝对小时；先预览冲突再应用，追加独立计划，不覆盖已有任务。硬错误禁止应用，资源竞争提示但允许。
