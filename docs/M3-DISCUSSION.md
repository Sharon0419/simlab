# M3三级供应与维修方式：需求讨论汇总

日期：2026-09-16。来源：用户本轮逐项确认。

状态：需求讨论稿，非完整执行契约；尚未实现。当前程序基线为v0.9.2，Git提交934e666。本文不改变已有版本行为，不代表M3完整阶段已完成。

2026-09-16：用户要求继续完善设计，已形成 [M3执行设计稿](superpowers/specs/2026-09-16-m3-supply-maintenance-design.md)。下方“尚待明确”事项在该稿中提出了具体设计默认值，仍须整体核对，不改写为用户先前已确认。

## 已确认：供应与调运

| 项目 | 规则 |
|---|---|
| 层级 | 基地、区域仓、中心仓三级 |
| 路径 | 仅沿已配置且适用的调运策略供货。高到低为a、b、c时，配置a→c才允许绕过b；否则不得自动直达 |
| 策略选择 | 优先调运时长短的策略；供货方无库存时改选有库存的下一策略 |
| 部分满足 | 允许按时长顺序从多个来源拆分数量，各批分别到货 |
| 全部缺货 | 保留待满足申请，合规来源补货或修复入库后重新分配，不绑定单一来源、不重复申请 |
| 触发模式 | 同一仓库、同一类部件选择临界库存触发或指定周期调运，两者互斥 |
| 库存位置 | 可用库存（不含已预留件）＋已申请未到货数量－尚未满足的需求；已申请数量包含在途，不能重复加计 |
| 申请数量 | max(0, 目标库存－当前库存位置)，即补到目标库存 |
| 周期申请 | 周期到点生成的申请持续有效；有货即可履行，不必等下个周期 |
| 首版运输能力 | 只计算调运时间，有货即可发运，不限制同时运输的数量，不产生运输容量排队 |

例：c需要6件，b有2件、调运2小时，a有10件、调运5小时，且两条策略均已配置，则从b调2件、从a调4件，分别到货。

## 已确认：维修方式与库存衔接

- 每类部件指定维修层级。原位作业与拆下件送修地点的具体衔接仍需在执行契约中明确。
- 修复性维修和预防性维修都支持原位维修、换件维修；同一部件可同时允许两种方式。
- 两种方式均适用时，每次维修触发按换件比例随机选择，不实行固定次数配额。修复性和预防性维修分别设置比例和作业参数。
- 选中换件但无备件时，等待备件，不重新抽样、不改走原位维修。
- 原位作业、拆卸/安装、拆下件维修分别配置时长及人员/设备需求。
- 装备完成换装、测试及必要准备后可恢复，不必等待拆下件修好。
- 拆下送修件修好后进入维修所在地公共库存，可供应其他地点，不绑定原送修基地。原位维修件仍留在装备上。
- 预防性换下件首版按“拆下→送指定维修地点→预防性作业与检测→合格后入当地公共库存”处理。用户说明此类部件通常不多，后续可细化。
- 预防性维修完成后，实际作业部件有效年龄归零，终身累计运行小时保留。拆换本身不清零实物年龄。
- 既有飞行小时检查不重置部件年龄的规则保持。

## 尚待明确的执行边界

1. 临界值相等时是否触发（已建议小于或等于）；初始库存不足如何处理；周期首个时刻及单位。
2. 多个地点竞争同一批库存的分配顺序、调运时长相同时的选择，以及时长采用固定值还是分布。
3. 未满足申请如何逐级传递并进入各级库存位置，尤其是多来源待满足申请的唯一记账，避免同一需求被多个来源重复计入。
4. 送修方向的策略配置、原位维修地点和指定维修层级的衔接。
5. 部件预防性维修的到期时钟、初始值、空中到期及与其他维修冲突的规则；不自动套用整机检查语义。
6. 原位修复、换件、年龄和现有多层LRU/SRU流程的兼容与守恒验证。

采购报废、供应中断、横向调拨等原M3内容尚未冻结本次实现范围。运输容量明确不纳入首版；不能因此宣称已满足原M3全部验收条件。
