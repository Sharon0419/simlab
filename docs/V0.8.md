# v0.8 项目库与再次出动保障

## 统一打开

双击原来的“启动SimLab.cmd”，默认进入项目库。项目库列出应用项目目录和曾经打开的外部项目，可按名称、说明或路径搜索；双击打开，或“复制模型为新方案”。复制创建独立ID和模型，不复制历史结果，也不改动源项目。旧cmd入口保留，但新案例不再逐个生成启动脚本。

在项目库搜索“飞机再次出动保障”，打开2组方案。其他电脑先导入便携包examples中的“飞机保障-2组-含1000次结果.simproj”。不可读取的项目显示错误，不自动删除。

## 半小时是一个完整作业

用户确认：回收后到重新具备出动条件的准备总时间为半小时，当前只执行一个作业，后续再拆多个工序。健康飞机落地后、故障飞机修复后请求准备资源；资源全部到齐后开始计半小时，等待时间另计。作业过程中不累计运行故障。

准备作业与维修共用现有资源池；按站点先到先服务、组合资源原子申请，队首不可满足时该站后续请求等待。按班次允许启动，已启动作业跨班继续。准备恰好在起飞时刻完成，先就绪再判定起飞。仍按准点凑齐整队起飞，不增加延迟起飞。

## 每日首波假设

2026-09-11用户明确选择“每天首波都假定健康飞机已提前保障好”。输入DAILY_READY=Y，在每天各选机池首波时刻使健康地面飞机就绪。故障机不修复，飞行中飞机不提前释放。

若健康飞机仍有排队或执行中的准备，记为“首波假设接续完成”，释放资源，实际已等待/工作时间仍保留；不计正常完成作业、不补算剩余半小时。每日就绪数量单独计架次，含本就就绪的飞机。该假设把每日首波准备能力排除在资源容量评估之外，不能据此得出保障组能完成全机首波准备的结论。

DAILY_READY=N则按资源排队实际准备，无每日就绪假设；新字段全留默认且PREP_TASK为空时保持v0.7行为。

## 输入配置

| 表/字段 | 示例 | 含义 |
|---|---|---|
| SimLabFlightRule.PREP_H | 0.5 | 一个完整准备作业的小时数 |
| SimLabFlightRule.PREP_TASK | TURNROUND | 指向Tasks定义的准备作业 |
| SimLabFlightRule.DAILY_READY | Y | 每日首波健康地面飞机假定已准备 |
| TaskResource.TID/RID/QTY | TURNROUND / GROUND_CREW / 1 | 每架准备需要1组；多行可同时要求不同资源 |
| ResourceAllocation.POINT/STID/RID/RQTY | 当前方案点/机场/GROUND_CREW/2 | 机场总共2组，每组一次保障1架 |
| ResourceStationData与ShiftProfile | 可选 | 未设置为连续可用；设置后按共同班次启动 |

同一选机池使用相同准备时长、资源作业和每日首波规则。单个作业要求超过总容量、没有共同班次或未知任务引用时阻止计算。

## 结果

“准备资源评估”分别显示作业请求、正常完成、首波假设接续、期末排队/在做、等待资源/班次、实际工作小时。“再次出动准备”显示首轮每架作业，按钮可导出全部轮次CSV。“取消原因”显示首轮取消的主要分类与起飞时状态分布；多个因素可同时存在，主要分类不是反事实因果贡献。

原“逐轮飞行CSV”增加取消原因和就绪快照；成功率、完整完成率仍分开。资源利用率在原资源页，分母是资源数×完整仿真时长，不能误作只在值班时段内的利用率。

## 兼容

扩展格式6支持读取1～5旧格式，保存和导出升级；旧版拒绝新格式。旧结果没有准备资源统计时保持空白，不伪造历史数值。原SIMLOX133表891字段不变，扩展表仍3张，新增2字段后共15字段。

本版未实现多工序网络、抢占、延迟起飞和计划维修；原厂数值等价未认证。
