# v0.7 开发计划：任务成功判定与评估闭环

状态：已交付，2026-09-11更新；原位置安装完成。原计划编写日期：2026-09-08，代码基线v0.6.0。实现与使用见V0.7.md，冻结规则见V0.7-SPEC.md，实测证据见VERIFICATION.md。以下保留原规划依据。

## 目标与优先级

优先回答“任务是否达到成功条件”，同时保留“是否完整飞完、何时故障、何时落地”。当前v0.6有三阶段、备用机、随机故障和返航，但完整完成不等于原厂成功点意义上的成功，不能直接把完整完成率叫FMSUC。

本版P0：任务成功点、指标口径、可复核结果；P1：阶段输入预览和CSV；后续：保障资源、计划维修、优化。指标口径未冻结前，不扩展概率优化或承诺原厂数值等价。

## 拟实现行为

使用已有MissionType.MSUCPT字段，按计划DURN的比例确定成功点。开发前核对本机原厂手册第183、565–576页的精确定义，形成V0.7-SPEC.md；不新增同义字段。固定飞行先支持，固定值守语义保持不变。

示例：09:00起飞、DURN=3、MSUCPT=5/6，成功点为11:30。若11:45在返航中发生故障，该任务可以已经成功，但没有完整完成；仍记录中止和实际落地。若11:00中止，则不成功。成功状态一旦达成不因之后的返航故障倒退。恰好在成功点故障的事件优先级必须在契约中明确并单测，不能依赖SimPy偶然的队列顺序。

MSUCPT=1默认用于保持“完成计划任务才成功”的用户预期；MSUCPT=0不能让未起飞或已取消任务自动成功。原厂单机成功与编队成功关联也须逐项核对后实现。

| P0 | 成功判定报告 | 每轮、每任务保留成功时间、原因、阶段、成员；1000轮结果能从明细复算 |

## 顺序与工期假设

按1名开发者、用户提供领域规则评审，采用相对工作日估算；没有承诺日历上线日期。两周总产能10人天，计划工作8人天、缓冲2人天。不是自动启动开发或定时任务。

| 顺序 | 工作 | 估算 | 依赖与检查点 |
|---|---|---:|---|
| A | 手册/字段核对、成功点及指标契约 | 1天 | 产出V0.7-SPEC及指标字典；争议指标先标记未实现 |
| B | 成功事件、同刻优先级、单机与编队关系 | 2天 | 依赖A；先确定性测试再接随机故障 |
| C | 逐轮聚合、迁移、历史结果兼容 | 1.5天 | 依赖B；不篡改历史结果，状态与数量守恒 |
| D | 结果页、CSV和阶段/成功点预览 | 1.5天 | 依赖A/C；UI、CSV、明细复算一致 |
| E | 1000轮案例、回归、桌面打包 | 2天 | 依赖B–D；保留对照参数、版本与种子 |
| 缓冲 | 边界语义、修复、评审变更 | 2天 | 不提前分配新功能 |

相关文件：operations.py/compiler.py处理输入，flight.py处理成功事件，engine.py聚合，project.py处理兼容，ui/window.py及modeling.py展示；新增tests/test_mission_success.py和docs/METRIC_DICTIONARY.md。可按必要性拆分指标模块，不先进行大规模重构。

## 验收案例

1. 无故障9任务：成功、完整完成均9；分别验证成功点0、5/6、1。
2. 成功点前、后各注入一次故障：同样中止，但成功判定不同；返航和维修时间不因成功标签改变。
3. 精确在成功点/落地时刻故障：符合冻结的事件优先级。
4. 飞机不足取消：请求数计入、起飞和成功不计入。
5. 同一v0.7引擎、相同参数，只改变可选飞机数2/4/12，各1000轮，对照备用容量；不可将随机流共享自动称为有效成对试验。
6. 同一物理场景只改变MSUCPT：实际故障/起落/维修事件不变，只改变成功统计。验证新增成功事件不改变故障预算。

发布门槛：当前100项回归通过；上述边界测试通过；源码与打包版桌面检查通过；1000轮复算与守恒通过；同版本种子可复现；旧v0.4/v0.5/v0.6项目可读；新版本结果不被旧版本误读。原厂对照未完成时明确标注“已实现字段口径、未认证数值等价”。

## 风险、预案与排除项

| 风险 | 级别 | 应对 |
|---|---|---|
| 成功点与完整完成混用 | 高 | 两套独立状态、独立列名；先冻结契约 |
| 成功事件改变随机轨迹 | 高 | 固定输入只改MSUCPT的轨迹不变测试 |
| 原厂指标聚合定义不完整 | 高 | 先输出本地清晰指标，保留未实现标记，不伪造对齐 |
| 人员/数据不可用 | 中 | 使用注明假设的确定性用例，参数等待不阻塞状态机和UI开发 |
| 超出两周估算 | 中 | 先延期分钟输入便利功能，保留成功判定、指标字典、CSV与验证门槛 |

本版不做保障人员排队、延迟起飞DTIM、阶段故障倍率、计划维修、冗余/RBD、成本优化及原厂全功能复制。返航期间多故障LRU仍沿用v0.6的落地后串行处理假设。后续版本见ROADMAP.md。
