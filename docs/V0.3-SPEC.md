# 0.3 实施契约：基地换 LRU、修理站维修 SRU

状态：功能与验证完成。使用 writing-plans 工作方式按可验证增量执行；验证记录见 VERIFICATION.md。

## 字段和范围

原 133 表/891 字段保留；MaterielStructure 允许 System→LRU→SRU 两层部件。带 SRU 的 LRU 必须 FRT=0、AFFRT=1，故障来自叶子；无 SRU 的 LRU 保持直接故障维修。LRU 下只允许 SRU，SRU 不得再有子件。不支持初始故障、冗余、随机检测、报废和采购。

ItemReplacement 描述基地 System/LRU 拆装，以及维修站 LRU/SRU 拆装；SURPT 按 Control.RMVFR 分为拆卸与安装。ItemRepair 仅为叶子直接修复；带子件的 LRU 不同时设置整件直接修复，避免叠加计时。SRU 故障件在同一修理站直接修复后入库；无备用 SRU 时父件等待该修复件。

新增独立表 SimLabDepotProcess（扩展版本 1），字段 LRU、STATION、DIAG_H、DIAG_TASK、TEST_H、TEST_TASK。检测与测试为固定小时数，任务引用 Tasks；允许显式 0 小时或空资源任务表示省略。每个实际维修路由必须配置，不能隐含省略。旧版本遇到新扩展表会明确拒绝，不宣称该表可由 SIMLOX 导入。

## 运行语义

每个库存 LRU 包含完整健康 SRU；StockAllocation 中 SRU 数量是额外散件，不包含已装在 LRU 内的子件。所有实物有独立标识，随父件运输的子件不能再计入散件库。一个实物只能占据一个位置，内部安装位置保留索引。

基地换件和故障 LRU 维修异步进行。维修链：送修→检测→拆下故障 SRU→释放拆卸资源→等待健康 SRU→申请安装资源→安装→测试→LRU 返库。坏 SRU 同时进入单独的直接修复流程。检测、拆装、SRU 修复、测试分别申请资源；待件期间不占用工位/人员。所有工序沿用班内启动、允许跨班完成规则。运输不占用维修资源。

层级模式保存每件健康叶子的剩余指数危险度预算；只在设备实际运行时扣减，健康叶子不因其他件故障被重新抽样。故障叶子修复后预算清空，在下次运行前重抽。旧非层级模型仍使用 0.2 路径，保持旧种子数值结果。
