# v0.12：两层冗余与保障多工序

适用日期：2026-09-16。本版落实本轮两项 P0，不增加混编和其他装备能力。

## 装备最低可用数量

在“模型数据→装备组成→最低可用数量”填写直接上级、部件型号和最低可用数量 k。
n 来自装备组成的每母件数量；同一直接上级下同型号部件是一组，k 必须为 1 到 n 的整数。未配置仍为原串联规则 k=n。组成结构页面同时显示 n 和 k。

System→LRU、LRU→SRU 两层都支持，各组之间仍要求全部满足。正常工作部件全部运行，无备用切换。任务中故障后仍满足 k 则继续当前任务，低于 k 则中止返航；返回后所有故障均尽早维修，等待人员/备件期间也不执行新任务。失去工作能力的分支停止运行暴露，其他可工作分支继续。已有寿命到限后完成当前飞行的规则保持。

## 工序方案

模型数据新增“保障多工序”：先建方案，再添加工序，最后绑定活动。

每道工序有方案内唯一标识、名称、业务动作、时长、分布、资源作业和紧前工序。多个紧前用逗号分隔；全部完成才开工。无相互依赖的工序可并行，但仍受人员设备和班次限制。通过“查看紧前 / 紧后”查看由同一份依赖配置推导的关系。

- 普通工序选“自定义作业”，如清洁、断电或校准，只计时和占资源。
- 原位维修包含原位修复、测试；换件包含拆卸、安装、测试；检测可放在前面。
- 拆下件包含检测、实际维修、测试。总成的实际维修动作调度内部故障件维修，不给总成重复增加修复次数。
- 必要动作只能出现一次且必须按顺序可达；循环、自依赖、缺失紧前、错误动作和资源配置错误在运行前提示。
- 按工序申请全部资源，齐备才开工，完成立即释放；缺备件时安装尚不占用其人员设备。开始后跨班做完，后续工序重新等待班次。
- 一台装备不同保障活动串行；单个活动内部可并行。拆下件维修独立进行，不阻止完成换装后的装备出动。

绑定方式：

| 活动 | 必填上下文 | 路径 |
|---|---|---|
| 在位维修 | 维修规则标识 | 原位或换件；混合方式分别绑定 |
| 到限换件 | 有寿命限值的修复性规则标识 | 到限换件 |
| 拆下件维修 | 部件、实际维修目的地、修复性/预防性类别 | 留空 |
| 出动准备 | 飞行规则中的任务类型标识 | 留空 |
| 日历检查 | 日历计划维修标识 | 留空 |
| 飞行小时检查 | 飞行小时检查标识 | 留空 |

已绑定活动采用方案工序时长和资源；未绑定活动继续使用旧设置。同一选机池使用同一准备方案。飞行规则的准备时长仍用于每日准备计划起点，实际准备完成时间由工序与资源决定。检查周期、到期时刻及初始小时仍在原检查表配置。维修活动方案使用已有 M3 维修规则；旧模式准备及检查也可绑定方案。

## 结果与示例

概览点击“新建冗余与多工序示例”：3 个动力总成至少 2 个可用，每个总成内部 2 个模块至少 1 个可用；包含并行检查、维修、出动准备与两类周期检查。

结果“保障多工序”可切换活动与工序明细，显示紧前/紧后、开工结束、依赖/业务条件/班次/资源等待。活动历时按开始至结束统计，不是并行工序时长之和。安装期间备件到限而重试时，每次尝试单独记录。界面为首轮，按钮导出全部轮次 CSV。

扩展格式为 12，可读取旧格式 1～11；旧软件不能读取格式 12。旧项目不启用新配置时保留旧执行路径，不自动改写项目库。安装验证结果以 docs/VERIFICATION.md 为准。
