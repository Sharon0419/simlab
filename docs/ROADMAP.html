# SimLab开发路线图（v0.6之后）

更新：2026-09-08。v0.6已完成本地交付和1000次案例验证；未来版本均未开始。本路线图为工作量与依赖计划，不是日历交付承诺，也没有创建自动开发任务。

## 目标

1. P0：建立可解释的任务成功评估，成功/完整完成/中止/取消及时间满足率分别计算。
2. P1：建立有资源约束的保障与计划维修，让等待和可用性可追溯。
3. P2：在同口径基础上做重复试验比较与原厂对照，避免把字段相同当作数值等价。

## 已交付基线

v0.3 LRU/SRU维修；v0.4固定时段值守；v0.5备用机及整队飞行；v0.6 TFOUT/TFRET三阶段、按阶段中止返航、落地维修。100项自动化测试；源码与打包版各27项桌面检查。当前未实现MSUCPT成功点、保障资源约束和计划维修。

## 相对排期

假设1名开发者、用户提供领域规则评审，每周5人天。10周共50人天，核心工作40人天、缓冲10人天（20%）。角色尚未落实，若产能变化须重新估算；阶段验收不通过不直接进入依赖阶段。

| 版本 | 相对窗口 | 工作/缓冲 | 交付重点 | 依赖 | 发布验收 |
|---|---|---:|---|---|---|
| v0.7 / P0 | 第1–2周 | 8+2人天 | MSUCPT、成功与完整完成分离、指标字典、CSV、输入预览 | v0.6 | 成功点前后及边界故障；1000轮明细复算；历史项目兼容 |
| v0.8 / P1 | 第3–5周 | 12+3人天 | 出动保障/回收周转拆分、人员与设备组合资源、班次与排队、准备未完不得起飞 | v0.7指标契约 | 人工可算的双任务资源冲突；无提前释放/负库存；资源等待与取消原因可追溯 |
| v0.9 / P1 | 第6–7周 | 8+2人天 | 第一批计划维修：日历触发、任务冲突、不可中断在飞任务、维修释放资源 | v0.8资源与状态 | 日历边界/重入/冲突测试；无故障情况下维护也可造成可解释缺口 |
| v0.10 / P2 | 第8–10周 | 12+3人天 | 参数扫描、2/4/12可选机受控比较、差值区间、原厂最小案例对照 | 前三版验收、原厂环境及同口径输入 | 固定版本/种子复现，单因素比较；至少3个确定性基准；原厂差异逐项解释 |

关键路径：指标契约 → 成功事件 → 资源状态 → 计划维修 → 受控比较。原厂手册核对与最小对照模型准备可提前进行，但没有原厂运行证据不能发布“与SIMLOX一致”。

v0.7详见[V0.7-PLAN.md](V0.7-PLAN.md)。v0.8/0.9/0.10在启动前分别编写字段映射与执行契约；本表不是这些模块已经完成设计的声明。

## 产能与责任

开发角色承担实现、自动化测试及打包；领域评审角色由用户或指定人员确认指标定义与保障规则；测试/分析角色可由开发者兼任，但须保留可重放证据。估算是规划假设，未指派真实人员。每版保留20%缓冲，不用新功能提前占满。

## 风险与预案

| 风险 | 等级 | 触发与预案 |
|---|---|---|
| 成功和完整完成混用 | 高 | v0.7契约审查未闭合则先保留本地指标名，拒绝伪装成FMSUC |
| 成功事件扰动故障随机轨迹 | 高 | 同物理输入只改MSUCPT时轨迹不一致，则停止发布并修复事件/随机流分离 |
| 新准备/周转作业双重计时 | 高 | v0.8先用无故障手算模型，准备和周转工序单独命名、定义重复边界 |
| 资源排队与计划维修导致死锁 | 高 | 组合申请和释放有确定性测试；不可满足资源组合运行前拒绝 |
| 缺真实故障/资源参数或原厂运行条件 | 中 | 使用标注假设的合成输入验证软件；原厂数值认证延期，不阻塞本地正确性验证 |
| 工期超估 | 中 | 优先保留语义、明细和回归，延期输入便利功能或大规模扫描；不降低正确性门槛 |

## 统一发布门槛

每版均需：旧回归通过；新增确定性边界用例通过；组件/设备/任务守恒；输入和结果模型哈希可追溯；1000次案例复算；源码与打包桌面通过；旧项目读取和新版本拒绝策略明确；文档与结果单位一致。概率区间仅反映模型内采样误差，不代替输入校准。

## 暂不排入本轮

冗余/RBD、非关键降级、阶段故障倍率、自动优化、成本分析、云服务、多人合并。延迟起飞DTIM及并行多故障维修须另立契约，不能顺带改变现有固定起飞和串行维修规则。
