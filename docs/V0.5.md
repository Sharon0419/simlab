# v0.5 飞行与备用机

新增独立 SimLabFlightRule（MTID、PREP_H）扩展。保存升级为扩展格式3，可以读取旧格式1和2；旧程序不能读取包含新规则的项目。

## 编辑和查看

“模型数据”选择 SimLabFlightRule，输入飞行类型与保障时长；在 OperationProfile 配置绝对起飞时间。部署于同一 Unit 的飞机共同参与选机；也可在站点范围选机，但不允许同一飞机同时属于两个重叠任务池。

“结果分析→飞行与备用机”显示计划、起飞、完整完成、中止、取消、架次及准备/就绪待命时间。每个重复保留任务成员及状态，首轮事件可查看保障和统一起飞。“值守计划”对飞行项目仅作时段查看，请用模型数据修改计划。

双击“打开飞机备用机案例.cmd”打开本次12架飞机、1000次结果。原单次和随机基线项目保留。

## 执行规则

- 每个任务池每天首次起飞前 PREP_H 小时开始全池保障；健康飞机保障完成进入就绪待命，当天未出动的就绪状态保留。
- 回收、修复后重新保障；包括最后一次回收。故障中的飞机必须修复后才能准备。
- 准点一次性选足任务NOS数量，按累计出动次数少者优先，同次数按编号；不允许单机先飞、不允许延迟起飞。不足则取消。
- 起飞后关键故障整队中止，备用机不得加入，修复也不恢复原任务。健康同伴重新准备，故障机进入原维修链。
- 当前返航耗时为0；保障没有资源竞争及运行故障；只有飞行累计故障暴露。不模拟轨迹、实际返航、准备有效期、预留指定主备机名单或原厂MSUCPT。
- 一个项目的飞行和固定值守不能混用；同池准备时长一致，飞行不得跨日，首波准备不得早于当天00:00。

## 指标

技术可用度仍包含准备、待命和执行中的健康飞机，不能当作已保障待命比例。飞行供给装备小时与准备装备小时分开。完整完成任务必须全程未中止；任务完成率不是原厂FMSUC的实现。

准备/待命按事件积分，详细曲线仍是采样显示。每轮重新初始化；均值95%区间和逐轮P05/P95不能互相替代。

## 案例

每天09/12/15点起飞，飞行2小时，三天；12架共同选机，每架动力/航电/电源/液压各1件，组件MTBF400h，对应串联整机MTBF100h。组件指数修复均值2h，零备件，无维修资源限制。无故障验收为9次、18架次、36飞行装备小时、27保障装备小时。

旧版案例还改变了准备故障暴露、部分供给及中止规则，不能把新旧结果差异全部归因于备用机。
