# v0.9 日历计划维修：执行契约

日期：2026-09-15。已实现固定飞行模式的日历计划维修；验证状态见VERIFICATION.md。对应原M2的下一增量，不表示整个M2完成。

## 目标

让设备在没有随机故障时，也可因到期的计划维修退出任务供给，并能解释等待、实际作业及恢复时刻。沿用现有任务状态和组合资源池。

## 初始实现口径（开发假设）

- 先实现固定日历时刻触发、固定持续时间的计划维修；运行小时触发、年龄更新另行实现。
- 在飞设备不被维修中断，到期后记录待执行，落地后再安排；等待执行不得被解释为实际维修作业。
- 已到期设备在地面不得领取新的飞行任务；不以首波健康机就绪假设清除计划维修。
- 维修作业沿用组合资源原子申请、班内开始及跨班继续的既有规则。
- 作业完成后，飞机仍需按其配置完成再次出动准备；计划维修不能自动消除随机故障。
- 到期、等待安全开工、等待资源、实际作业及完成分别记录；仿真期末未完成保留状态，不算完成。

## 字段与执行边界

本机SIMLOX 2017字典MaterielPM含PMINT、OPID、ATIM、DTIM、ENREG等更广的规则，当前实现没有这些完整语义。因此使用独立SimLabPlannedMaintenance，保留原133表891字段及Control.ENPM=N，不声称支持原厂预防维修算法。

| 字段 | 含义 |
|---|---|
| PMID | 全局唯一计划标识 |
| SID / USTID | 系统与部署位置；USTID必须与SystemDeployment输入位置完全相同，适用于该部署的每一架飞机 |
| FIRST_H | 首次到期，0≤时刻<仿真时长 |
| INTERVAL_H | 以首次到期为锚点重复；零或留空仅触发一次；期末时刻不触发新到期 |
| DURATION_H | 每次固定维修时长，必须大于零 |
| TASK | 引用Tasks/TaskResource；留空无资源约束，否则须有正数量资源需求、足够容量及仿真期内共同班次 |

同一飞机重复到期逐次排队，不合并、不重置日历；按到期时刻、计划标识、飞机标识稳定排序。已在排队或执行的准备不抢占；故障飞机先完成纠正性维修。计划作业结束后逐个处理已到期的后续计划，全部结束再重新准备。首波假设不能跳过到期计划，也不能跳过计划维修后的真实准备。后续日历首波仍可对已经恢复正常准备状态的飞机应用既有假设。

仅支持固定飞行选机池，连续使用及值守输入明确拒绝。计划维修不更换部件、不复位寿命或故障时钟。资源申请与作业状态计入停机；等待落地、既有故障维修、前序准备/计划的延后时间单独统计，不能再次从可用度扣除。多个积压工单的延后可重叠，不能视为设备互斥状态时间之和。

同刻先处理落地和已结束准备，登记到期并执行/结束计划维修，再做准备和起飞判断；正时长准备未完成不能起飞。无新增规则时保持旧物理路径和旧结果键。新增结果位于mission.planned，各轮明细完整保留，界面展示首轮和跨轮均值。

格式7读取旧1–6；保存/导出升级到7，旧版读取器拒绝7。单计划最多10000个到期时刻，工单数×重复次数≤200000，避免无限积压扩展。

## 必须先写出预期的确定性案例

1. 无故障设备第2小时到期、维修1小时、无资源等待：实际维修区间为[2,3)，此期间不可派发任务。
2. 飞机第2小时在飞，到第3小时落地：第2小时记录到期，实际维修不得早于第3小时。
3. 两架地面飞机同时到期，共享1组资源，各作业1小时：不能同时占用资源，总作业量为2组·小时。
4. 计划维修完成后配置0.5小时再次准备：准备完成前不能起飞。
5. 首波假设开启且计划维修已到期：假设不得跳过计划维修或恢复故障。
6. 期末仍在等待或作业：明细保持未完成；实际作业积分截止于仿真结束。
7. 未配置计划维修的旧案例：固定版本、种子下保持现有物理轨迹及结果。
