# SimLab 0.4.0 — 固定时段值守

## 启动与使用

双击原来的 `启动SimLab.cmd` 或 `dist/SimLab/SimLab.exe`。便携包为 `dist/SimLab-Windows-v0.4.0.zip`，保留整个 SimLab 文件夹。

1. 进入“07 值守计划”，点击“新建值守示例”，创建独立项目。
2. 左侧选任务类型，配置目标数量、最低保障、优先级、补位小时及允许连续不达标小时；点击“保存所选任务规则”。该类型的所有窗口共同使用规则。
3. 右侧输入唯一计划名称、系统、单位/站点、第几天开始、天数和每日时段，使用左侧当前规则。点击“预览新增计划”查看绝对小时及潜在设备竞争，再点击“添加预览计划”。修改输入会使旧预览失效。
4. 在“仿真实验”校验并运行。结果页查看“任务供需”“值守达标”和“不达标时段”；“导出任务 CSV”包含新增指标。

天数以仿真起点为第1天，不使用电脑当前日期。每日时段要求0≤开始<结束≤24；跨午夜请在模型数据中配置固定时长窗口。计划不得超出仿真期，不自动延长仿真或维修班次。批量新增不会覆盖已有任务；共享运行剖面在必要时为所选单位分支，其他单位不受影响。重叠提示代表可能共享设备，不能据此直接认定容量不足；仿真会计算实际竞争。

## 输入契约

原 SIMLOX 字典仍为133表/891字段，增加独立 SimLabDutyRule，与原有 SimLabDepotProcess 合计2表/11字段。

| 字段 | 规则 |
|---|---|
| MTID | 唯一任务类型引用 MissionType.MTID |
| MIN_QTY | 1至目标数量的整数，最低保障设备数 |
| PRIORITY | 正整数，默认1；越小越优先 |
| RELIEF_H | 非负有限小时，默认0；窗口开始后的分配需要准备的时间 |
| TOLERANCE_H | 非负有限小时，默认0；允许的最长连续不达标时间 |

目标数量仍取 MissionType.NOS。原 MNOS/MNOSA 保留既有受限契约，不能冒充新的保障标准；中文编辑器保存目标时同步这些受限数量字段。无扩展规则时最低数量=目标数量，优先级1、补位0、容忍0。

## 运行语义

固定窗口为 [开始,结束)。到点尽量分配，即使不足也继续值守并记录缺口；迟到或补位不会顺延终点。开始时可用设备直接上岗，开始后的新分配经过 RELIEF_H 准备。准备设备被预留、不能重复分配，不计供给及运行故障；设备可用度仍将健康的准备设备计为可用。

空闲设备按优先级、开始时间、任务标识分配；不抢占已值守或已预留的设备。延迟开始的高优先任务不会抢走早先任务的设备。设备故障立即退出，维修沿用0.3的 LRU/SRU 流程；有备用设备可独立补位。最低保障不足时不取消窗口，继续尝试补位。窗口结束取消未完成准备，设备可参与下一个窗口，旧准备回调不能错误覆盖新分配。

准备是固定等待，不建模真实路径、车辆运输容量或人员资源，准备期间不累计运行故障。不支持多系统联合任务、能力降级、抢占或计划性维修。

## 指标口径

- 设备小时满足率 = 实际供给设备小时 / 原计划目标设备小时。不足不缩小分母。
- 最低保障达标率 = 达到最低数量的任务窗口小时 / 全部任务窗口小时。并发窗口分别计时，不按数量加权。
- 单窗口合格：最长连续低于最低数量的时间 ≤ TOLERANCE_H（浮点容差1e-9小时）。只容忍短缺持续时间，不改变供给积分；补齐不抹去过去记录。
- 窗口合格率按窗口数计算，汇总结果为各独立重复试验的均值。
- 值守达标表的“最长连续均值”是每轮最长连续不达标时间的均值；合格率逐轮判定后平均，不能用该均值重新推算合格率。
- 任务目标、最低线与实际供给图为跨任务合计及跨重复均值，按 RCINT 采样，可能漏掉短缺；合计达到最低线不代表每个任务都达标。
- 不达标时段明细为首轮最多5000条，同一任务相邻且供给/原因相同的区间合并；截断时界面标识，总指标仍覆盖全部事件。跨午夜或任务边界不将不同窗口连成一段。
- 原因分摊先计部署不足，再计本任务已预留补位数，其余按稳定设备顺序归入任务占用或维修状态；这是目标缺口的描述性分摊，不是因果贡献。原因变化可能将同一连续不达标段拆为多行。

CSV保留原列并增加 minimum、priority、relief_hours、tolerance_hours、minimum_rate、qualified_rate、below_hours、longest_below_hours，含运行ID、种子和模型指纹；区间明细随完整项目包保存。

## 兼容与验收

扩展格式版本提升为2。可读取旧版本1及无扩展版本标记的项目；保存/导出后标记为2。旧应用不能打开新版保存的项目，应使用新版；升级保留旧程序备份，项目覆盖仍保留数据库 .bak。历史结果没有新指标时不伪造达标值。

解析基准：0–8小时目标/最低均为2台；第2小时一台故障，备用设备准备0.5小时，则供给15.5设备小时、缺口0.5设备小时、最低达标率93.75%、最长不达标0.5小时。容忍0.5小时合格，容忍0.25不合格，结束仍为8小时。

另验跨终点取消准备、同刻交接、优先级不抢占、连续短缺跨采样保留、最低与目标区别、参数拒绝、按日生成边界、共享剖面隔离、固定种子与项目往返。实际发布验证见 VERIFICATION.md。
