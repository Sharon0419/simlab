# v0.9.1 飞行小时检查

2026-09-15。M2新增固定飞行的累计在空小时检查；老化、检查发现隐患及可靠性改善尚未实现。

## 输入

“模型数据 → 04 维修与保障作业 → 飞行小时检查”：

| 字段 | 含义 |
|---|---|
| CHECKID | 检查标识，同表唯一；每项检查独立计时 |
| SID、USTID | 系统与部署位置，须与系统部署完全对应 |
| INTERVAL_H | 检查间隔，累计实际在空小时 |
| DURATION_H | 每次固定检查作业小时 |
| TASK | 引用资源作业；留空无资源约束 |

“逐架初始检查小时”：CHECKID引用检查，ASSET_NO是该部署内从1开始的飞机序号（对应飞机编号末尾001等），INITIAL_H为距上次该项检查已飞小时，未填的飞机默认0。此数值不是部件年龄。初始已达阈值的飞机在仿真开始时到期。

小时须有限非负，间隔及作业时长至少0.000001小时，以避免浮点同刻循环。仅支持固定飞行模式；不可满足的资源或共同班次在运行前拒绝。计划工单上界×重复次数不超过200000。

## 已确认的执行规则

- 从起飞至落地计时，含正常返航、中止返航；地面准备、等待及维修不累计。
- 起飞时剩余小时不足仍可起飞；空中到期继续当前任务，落地检查，不再领取新任务。随机故障仍执行原来的中止返航规则。
- 每项每架每周期最多一张待办检查工单，持续超限不重复发单；历史超限小时单独保留。
- 检查实际完成后本项小时归零，再累计一个完整间隔；不重置另一项检查、不更换部件、不重置年龄和故障预算。
- 与日历维修同时到期时分别串行，不互相抵消；同刻先登记日历维修，再登记飞行小时检查。已到期工单按队列依次处理，已有准备/故障维修不抢占；全部完成后统一准备一次。
- 启用飞行小时检查的模型在首波前完成计划维修后也立即执行修后准备，避免在首波时才开始准备。
- 浮点阈值比较使用1e-12的相对/绝对容差。达到阈值的期末时刻也记录到期，期末未完成不计作完成。

## 结果

“飞行小时检查”显示首轮逐架计时和检查工单，两个按钮分别导出全部轮次计时及混合维修工单CSV。“计划维修汇总”合计日历和飞行小时作业，资源等待与实际作业继续计入停机。

计时列：initial_hours初始、flown_hours本轮在空、hours_since_check距上次检查、completed_checks完成次数、due是否已到期。工单trigger区分calendar和flight_hours，cycle_hours为该次周期累计，overrun_hours为超过阈值的小时。

验证恒等式：初始小时+本轮在空小时=已完成检查工单cycle_hours之和+当前hours_since_check。跨检查之间不能把飞行小时相加，否则会重复计数同一飞机的飞行。

旧项目格式1–7可读，保存升级至8，旧版拒绝8。没有新检查规则时，旧结果结构和物理数值保持不变。原SIMLOX字典不修改；新增两张独立扩展表，不宣称原厂算法等价。

示例：项目库搜索“飞机飞行小时检查”，或导入docs/cases/2026-09-15-aircraft-inspection/飞机飞行小时检查.simproj。每3小时检查1小时、初始小时逐架错开，是合成验证案例。
